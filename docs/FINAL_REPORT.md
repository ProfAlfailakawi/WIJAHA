## 5. قرارات معمارية اتُّخذت وتحتاج تأكيد المؤسسين

1. **البنية المعمارية (ADR-001):** اعتماد **Modular Monolith** يجمع Express API + Vite React SPA + Drizzle PostgreSQL في مستودع وتشغيل موحّد على المنفذ `3000` لسرعة الصيانة والبساطة التشغيلية.
2. **حوكمة الذكاء الاصطناعي (ADR-002):** فصل التوليد عن التحقق عبر دالة حتمية (`verifyAndHardenResultPure`) تحذف أي `ruleId` غير مسترجع وتفرض `expert_review` آلياً على كل مناسبة عالية الحساسية.
3. **نسب توزيع عوائد الخدمات المشتركة والفردية:** تُركت الحقول `expertSharePct` و`platformSharePct` بقيمة `null` افتراضياً وقابلة للضبط لكل طلب في لوحة الإدارة دون فرض أي نسبة ثابتة في الكود.
4. **القرارات الـ 12 المفتوحة للمؤسسين (القسم 35):** حسم الاسم النهائي بعد الفحص القانوني، اتفاق المؤسسين، قائمة الدول الـ 10–15 الأولى، التسعير النهائي بعد المقابلات، والكيان القانوني وبوابة الدفع.

## 6. الأسرار ومتغيرات البيئة المطلوبة للإنتاج الحقيقي (بالأسماء فقط)

تُضبط عبر لوحة الأسرار في بيئة الاستضافة (دون كتابة أي قيمة سرية في الكود، راجع `.env.example`):
- `DATABASE_URL` — رابط اتصال قاعدة بيانات PostgreSQL السحابية.
- `SESSION_SECRET` — مفتاح توقيع جلسات المصادقة الآمنة.
- `AI_PROVIDER` (`mock` أو `gemini`) و`GEMINI_API_KEY` — لتفعيل التوليد اللغوي الحي عبر Gemini مع بقاء طبقة التحقق الصارمة.
- `PAYMENT_PROVIDER` و`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` (أو مفاتيح Tap) — عند تفعيل التحصيل الفعلي.
- `EMAIL_PROVIDER` و`SMTP_URL` — لإرسال الروابط السحرية وإشعارات طلبات الخبراء عبر البريد الفعلي بدلاً من سجل الخادم.
- `APP_URL` — النطاق الرسمي للمنصة.

## 7. خطوات التشغيل والنشر (Staging ← Production)

1. **التشغيل المحلي بأمر واحد:**
   ```bash
   npm install
   npm run dev
   ```
2. **تشغيل الاختبارات والتقييم الذهبي قبل أي نشر:**
   ```bash
   npm run lint
   npm run test:unit
   npm run evals
   npm run build
   ```
3. **النشر على Staging ثم Production:**
   - دفع تغييرات المخطط إلى قاعدة بيانات البيئة المستهدفة (`drizzle-kit push`).
   - ضبط متغيرات البيئة في خدمة الاستضافة السحابية (Cloud Run).
   - تشغيل الخادم الإنتاجي عبر `npm start` (`NODE_ENV=production tsx server.ts`).

## 8. ما يجب على البشر فعله قبل الإطلاق التجاري الرسمي

1. **اعتماد المحتوى البروتوكولي:** مراجعة القواعد التجريبية وإدخال القواعد المعتمدة رسمياً من الخبيرين عبر `/admin/rules` وتوسيع مجموعة الـ Evals الذهبية إلى 200 سؤال معتمد.
2. **تنفيذ مقابلات التحقق واختبار قابلية الاستخدام:** باستخدام الأدلة الجاهزة في `docs/research/interview-guide.md` و`docs/research/usability-test-plan.md`.
3. **المراجعة القانونية:** اعتماد نصوص الشروط والخصوصية وحدود المسؤولية في `/legal/*` من مستشار قانوني مرخّص وإزالة شارة المسودة القانونية.
4. **اتفاق المؤسسين وتفعيل بوابة الدفع:** توثيق نسب الإيرادات والملكية الفكرية وربط حساب التاجر الرسمي.
